# runs/

Each training run writes `runs/<name>/`:

| File | Contents |
|---|---|
| `config.yaml` | fully resolved config + `_meta` (git commit, torch/CUDA version, GPU) |
| `curve.csv` | one row per evaluation: step, LR, train loss, dev loss, dev macro-F1 (@0.5 and tuned) |
| `metrics.json` | test metrics @0.5 and with dev-tuned thresholds, CIs, per-class, Ekman/sentiment, ECE, params, time |
| `predictions.npz` | dev/test probabilities and labels (for analysis and paired tests) |
| `errors.jsonl` | the 50 most confident test false positives (`failure_category` filled in by hand) |
| `best.pt`, `tokenizer/` or `vocab.txt` | best checkpoint (trainable weights only for LoRA) |

Only small summaries are committed: `tfidf_lr/{config.yaml,metrics.json}` (real CPU run)
and `tfidf_sweep.json` (dev-set hyperparameter search). `runs/analysis/` is
regenerated by `make analysis`.
